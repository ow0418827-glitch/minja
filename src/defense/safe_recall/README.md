# 安全记忆召回第三版：代码导读

本目录实现[第三版数学设计](../../../docs/SAFERECALL_V3_INTENT_AUTHORIZED_DESIGN.md)的独立原型。原购物循环未改动；从本目录的回合驱动启用新路径。代码区分**本次授权的历史字段**、**只可建议观察步骤的普通记忆**和**当前页面证据**。

## 阅读顺序

| 层 | 文件 | 职责 |
|---|---|---|
| 数据契约 | [contracts.py](contracts.py) | 当前请求、意图假设、字段引用、目标、观察与结果 |
| 授权 | [intent.py](intent.py)、[authorization.py](authorization.py) | 解释当前请求，对合理解释取权限交集 |
| 历史来源 | [providers.py](providers.py)、[history.py](history.py) | 来源接口、摘要核验、完整查询回执、最近记录与时效 |
| 普通记忆 | [compiler.py](compiler.py) | 将历史建议限制为有限观察操作 |
| 当前证据 | [ledger.py](ledger.py)、[adapters.py](adapters.py) | 页面/商品/选项版本、真实环境适配 |
| 决策 | [model.py](model.py)、[gate.py](gate.py) | 意图与候选评分、字段/规格/价格及购买检查 |
| 数学审计 | [scheduler.py](scheduler.py)、[calibration.py](calibration.py)、[risk.py](risk.py) | 真实抽样的相对熵预算、可选解释集合校准、完整策略误购审计 |
| 编排 | [runner.py](runner.py)、[cli.py](cli.py)、[audit.py](audit.py) | 独立购物回合、单任务入口与离线统计入口 |

依赖从数据契约流向决策和回合编排。除环境适配和命令行入口外，核心模块不导入旧购物智能体或实验评分数据。

## 能力边界

- 当前图片同款：用户图片与当前商品图片都可取得时，模型比较它们并检查当前页面、商品和选项。图片下载只允许显式列出的当前商品图片主机。
- 既有实验的外部商品图片地址不可用时，可用 `--image-cache-records` 指定受控的本地图片记录目录，并用 `--image-cache-only` 禁止对缺失图片发出外部请求。缓存必须与当前页面给出的商品编号和图片地址一致，图片内容摘要重新校验；缺失或不一致时仍按缺证处理。缓存应由独立评估资产维护，不能由普通记忆提供。
- 复购：只有本次请求提出历史引用，且订单接口给出同一账户、对应范围、已认证且未过时的**完整查询回执**时，才解析“上次”。旧商品编号从不直接成为本轮可执行商品句柄。
- 尺码：旧购买记录不能证明合身。已确认的品牌尺码标签仅能用于同品牌；已确认的身体尺寸需要当前尺码表的区间包含校验。找不到尺码表或尺寸体系不明时保留缺证状态。
- 其他偏好：只从有来源核验的确认记录按字段接纳。当前明确约束覆盖对应历史字段；普通记忆不能创建授权或来源状态。
- 程序经验：任意普通历史文本只送入有限操作编译器；它输出的观察顺序建议经相对熵预算投影并真实抽样，不能输出商品编号、购买动作或新的阈值。
- 来源默认不可用。仓库现有仿真购物结果不是账户订单服务，也不是用户确认。测试夹具带有签名的“夹具”标记，正式配置默认拒绝。
- 当前模型的匹配分数是排序特征；默认数值阈值尚未经独立完整策略审计，**不能称为误购概率证书**。用户意图模型的候选集合也尚无独立校准数据；[calibration.py](calibration.py)提供分割保形阈值计算，但部署前仍需真实标注及候选覆盖核验。

## 运行一个本地商城任务

先启动项目既有的商城服务，并准备已有的私有模型配置。以下命令每次只运行一个回合；不会批量运行旧实验。

~~~powershell
& 'D:/Anaconda/envs/minja-vision/python.exe' -m src.defense.safe_recall.cli --session example-session --subject local-user --request '购买当前图片中的同款商品' --image 'D:/path/to/current.png' --image-host '当前商品图片的可信主机名'
~~~

默认运行会完成取证与购买判断，但因缺少独立完整策略风险审计，不提交购买；结果说明“待校准”。仅在受控仿真研究中显式添加 --research-execute，才允许未经统计发证的原型提交仿真购买。此开关不等于风险证书。

若请求需要订单或确认记录，需要由外部可信服务产生签名的查询快照，再同时提供来源快照路径、已配置来源名称和验签密钥环境变量名。密钥环境变量内容为十六进制，至少三十二字节。程序不生成、保存或猜测来源密钥。来源签名只证明已配置来源作过陈述；记录是否正确、当前是否适用以及用户是否授权本次使用仍分开检查。签名快照的回执必须覆盖主体、记录种类、类别、选择语义、完整记录编号、快照版本与签发时间；五分钟内有效，提交前再次查询。运行结果单独写入 src/output/safe_recall_v3/，不覆盖旧实验结果。

命令行使用的模型配置和正在运行的商城服务仍需自行提供；本目录没有预置真实订单服务、用户偏好确认服务或可证明的误购风险阈值。真实在线购买或大批量付费评估均不由测试命令自动启动。

## 离线统计

独立评分层准备一个包含 family（商品族）、purchased（是否购买）、wrong_purchase（是否误购）的任务数组。同一商品的改写应共用同一商品族。执行：

~~~powershell
& 'D:/Anaconda/envs/minja-vision/python.exe' -m src.defense.safe_recall.audit 'D:/path/to/offline-task-outcomes.json' --delta 0.05
~~~

每个商品族只有一次测试时，输出单侧精确二项上界；每族有相同且预先规定的重复次数时，输出簇级保守界。购买覆盖率、每任务误购和购买条件误购分开报告。评分真值只在离线统计入口读取，不能回传给[runner.py](runner.py)。
