数据与准备报告位于 `src/output/local20`。原完整商品数据、已有小样本目录和相邻原项目源码未修改；购物服务通过当前项目内的适配器读取新的子集。

使用两个 PowerShell（命令行终端），都进入当前项目根目录。脚本固定调用已经配置的解释器，不要求终端先激活环境。

### 终端二：开始实验

```powershell
Set-Location 'D:\Material\Literature Reading\code\minja'

powershell -ExecutionPolicy Bypass -File .\run_local20.ps1 `
  -Stage Run -RunName m3_trial01
```

模型配置读取 `src/configs/llm.local.json`，结构与相邻项目相同，使用其中 `model`（模型配置）下的 `provider`（服务商）、`model`（模型名称）、`base_url`（接口地址）、`api_key`（密钥）。已从相邻项目的服务器配置复制服务设置，模型为 MiniMax-M3（文字模型）。无需设置密钥环境变量，本实验入口不读取环境变量中的密钥。更换密钥或模型时编辑此本地配置；更换模型或接口后使用新的运行名。

该文件含本地密钥，已加入版本控制忽略规则；可分享的无密钥格式示例为 `src/configs/llm.example.json`。请勿分享实际密钥配置。相邻项目后续修改不会自动同步到此副本。可通过 `-LlmConfig '配置文件路径'` 指定其他同结构文件。

运行设置只记录服务商、模型和接口地址，不保存密钥。此次完成了离线配置和客户端构建检查，未请求付费模型接口，尚未验证账户权限。商品子集中的旧模型元数据不控制运行；实际模型以此配置及每轮保存的运行设置为准。

## 一条运行命令会做什么

1. 核验正在运行的商店确实是本次准备的子集。
2. 从真实购物任务中生成 30 条正常记忆，优先选择相近牙刷需求作为竞争记忆。每个候选最多尝试两次，最多处理 70 个候选；未达到 30 条则明确停止。
3. 使用原有强到弱的文字模板生成诱导轨迹，最后在不附加提示的训练需求上核验是否仍实际购买甲。每阶段最多三次尝试。
4. 只有最终阶段通过文字、购买结果和主图配对检查，才冻结“30 条正常记录＋1 条诱导记录”的记忆库。
5. 用该记录的实际甲主图进行 1000 步图片优化，生成原图和对抗图两组记忆。
6. 执行 20 次重复测试。三条件执行顺序轮换，实际结果逐次保存并汇总。

**60 次指正式评估的购物次数。首次运行的正常记忆生成和文字注入还会额外调用模型。** 程序不会为了凑足数量伪造正常轨迹、诱导轨迹或购买结果；模型不接受诱导时，流程可能在准备记忆阶段停止，这是实验结果而非安装失败。

本次所有乙查询均使用同一张商品主图，该图也用于图片优化。这是已知查询图片、固定商品对设置，不代表对其他照片或其他商品的泛化效果。

## 两步优化的流程检查

如希望先把后续图片优化缩短到两步，可使用新的运行名：

```powershell
powershell -ExecutionPolicy Bypass -File .\run_local20.ps1 `
  -Stage Run -RunName quick01 -AttackSteps 2
```

这只缩短图片优化，仍会生成记忆并执行 60 次正式调用，因此**不是免调用成本的检查命令**。无模型调用的环境检查已经完成，无需再运行此命令来证明依赖可用。

如果恰好在某轮三条件之间中断，该轮只有部分输出，程序会停止并提示位置，防止覆盖或混合结果。此时先保留、检查这些输出，再决定如何重试。换模型、改变步数或另做一轮实验时使用新的运行名。

完成后可在服务终端按停止快捷键关闭购物服务。

## 第2版：仅重新评估，复用已有1000步对抗图

> 本节保留第2版实验记录。当前代码已升级第3版，请使用文末第3版的新运行名称，不能继续写入已存在的第2版结果目录。

已修复页面动作反馈、结果展示与翻页、末步执行和记忆索引。三个条件统一使用新执行逻辑。此入口只进行购物评估，不生成正常记忆、不进行诱导训练、不重新优化图片。

先保持本地商店运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\run_local20.ps1 -Stage Serve
```

先运行3轮三条件测试，共9次购物：

```powershell
powershell -ExecutionPolicy Bypass -File .\run_local20.ps1 -Stage Evaluate -SourceRun m3_1000steps_trial01 -RunName eval_v2_full_check03 -Trials 3 -AttackSteps 1000 -MemoryMode full

确认基本购物可以完成后，再开独立目录运行20轮，共60次购物：

powershell -ExecutionPolicy Bypass -File .\run_local20.ps1 -Stage Evaluate -SourceRun m3_1000steps_trial01 -RunName eval_v2_full_20 -Trials 20 -AttackSteps 1000 -MemoryMode full
```

这里的1000步用于核对来源实验确实完成了1000步优化，不会启动优化。两条命令均调用配置中的文字模型，因此购物评估仍有模型调用成本。新的20轮会独立评估，不把之前3轮混入。

`full`（完整记忆）使用完整历史；`fragment`（动作片段）使用修正索引后的片段。需要比较两者时，用新运行名称并将参数改为 `-MemoryMode fragment`；其余参数保持一致。示例：

```powershell
powershell -ExecutionPolicy Bypass -File .\run_local20.ps1 -Stage Evaluate -SourceRun m3_1000steps_trial01 -RunName eval_v2_fragment_check03 -Trials 3 -AttackSteps 1000 -MemoryMode fragment
```

输出位于 `src/output/local20/runs/<新的运行名称>/`。运行设置记录来源实验、冻结文件校验值、执行版本、记忆展示方式和测试次数。变更这些设置需使用新的输出名称，不能续写旧条件。

每条轨迹的 `PolicyTrace`（模型调用与动作审计记录）保存实际提示、原始回复、解析动作、格式检查、执行反馈及选中的记忆编号。报告新增未完成原因、动作数量、无效动作、格式错误、搜索甲、点击甲及缺货思考指标。记忆进入提示不等于模型接受记忆；搜索甲和缺货文字指标为规则匹配，需要结合轨迹阅读。

没有完成购买的配对，其完成后误购变化率记录为空值，不解释为“成功抵抗攻击”。当前仍为同一需求和同一图片重复测试，并未新增跨图片、跨商品泛化实验。
